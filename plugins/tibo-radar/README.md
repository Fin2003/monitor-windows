# Tibo 雷达

Monitor 内置插件。源码、状态规则、独立面板入口位于本目录。

## 使用

完成 `npm run build` 后重新启动 Monitor，在插件管理中启用 **Tibo 雷达**。
“预览”切换副屏，“管理”打开独立面板。设置按钮可调整检查间隔或暂停检查。
首页只保留最近两个明确 Reset 事件，主要数字 56px、事件时间 32px，帖子正文 34px、原文弹窗 36px。
每个 Reset 一张卡片，以图标和连接线对应预计与完成时间；绿色表示已完成，蓝色表示等待，橙色表示超时未确认。原文只露一行，点击阶段或原文可展开。
小屏上下排列，大屏左右排列。Banked 不生成卡片、不显示预告或待发放状态，仅保留最近 30 天内最新两条可点击的 `Banked +1` 标记。Banked 帖子筛选同样限制最近 30 天；全部帖子保留历史原文。此标记表示帖子类型，不代表账户余额或发放确认。
重点适配当前 641×429 副屏。480×320 等更矮屏幕允许事件区滚动，不缩小正文。支持深浅主题与减少动态效果。
公开抓取无需 X 登录。默认每 120 秒检查一次；失败后退避，最多正常间隔的 8 倍。
这是轮询监测，不是服务端实时推送。关闭 Monitor 后不继续监测。

## 数据来源

1. 复用 Monitor 的 `ScraperSession`。`persist:tibo-radar-anonymous` 免登录加载主帖；只有开启回复辅助并检测到 `persist:tibo-radar-public` 的 X 登录态后，才读取回复页。
2. FxTwitter 补全原文、原始发布时间、引用帖、回复目标；仅把 Tibo 本人的发言当作公告。
3. Codex Resets MCP 每 15 分钟补充历史帖子 ID。绝不把它的 `observed` 时间当作完成帖发布时间。
4. 每轮最多补全 15 个 ID，分批并发 3 个；优先新帖，历史逐步补齐。失败不清空已有记录。

X 匿名预览可能限制条数或要求验证；FxTwitter 也可能限流。回复辅助关闭时不访问回复页，历史补充里混入的回复 ID 也不会进入主帖列表。
因此不承诺全部帖子、零延迟或不漏帖。界面显示成功检查时间、异常与待补全数量。
`帖子` 显示本地已收录的全部 Tibo 帖子原文，按发布时间倒序，每次展开 20 条，向下滚动或点击加载更多。普通帖子为灰色；reset 相关帖子按预告、完成、banked、提及、待判断标记。
`事件` 只显示最近两个明确 Reset 事件；提及和待判断保留在帖子列表。帖子页提供全部 / Reset / Banked 筛选，类型标记也可点击筛选。这里的全部是已收录数据，不代表 X 完整历史。

## 状态规则

- 明确未来措辞为预告；明确完成措辞为完成。疑问、否定及不明确的 reset 提及不确认重置。
- 通过引用或回复链对应预告与完成；不凭时间邻近硬配对。独立完成帖仍计入最近一次普通重置。
- 显示时区默认北京时间，可在监测设置改为太平洋时间、UTC 或日本时间；这只改变显示，不改变时间判断。未注明时区的原帖按 America/Los_Angeles 解析，自动处理夏令时；明确 PST/PDT 则尊重原文固定偏移。已收录的普通重置帖明确出现过 `6pm PST`；另一个 Banked 帖中的 `8pm PT` 是注册截止时刻，不是重置时刻。完成通知发布时间分散，不能反推固定执行小时，因此默认时区仍是可撤销的假设。
- 主帖明确时刻或相对间隔优先；开启回复辅助后，才用已抓到的三天内 Tibo 帖子/回复辅助确定时间。仅有日期且附近没有可靠时刻时，显示“未通报时间”和另行标识的既有 01:00 规则预测。连日期都没有则不生成具体时间。
- 只有主帖时间或有证据的附近关联时间才参与到时、超时和两小时观察；规则预测不触发超时或额度确认。时间流逝绝不会自动确认重置。
- Banked reset 为单独的额度发放提示，不生成普通重置 ETA，也不更新最近一次普通重置。
- 没有可核验日期或时刻的预告保留待确认，不捏造倒计时。
- 旧的未配对预告保留历史；当前预告只显示最新完成通知之后的预告，或预计时间仍晚于该完成通知的预告。
- “最近一次重置”记录的是完成通知发布时间，不是后台实际执行日志。

状态缓存位于 Electron `userData/tibo-radar-state.json`；设置保存在原有配置的 `tiboRadar` 键。
未配置当前判断渠道的模型时，含 reset 的帖子保留待判断，不按本地正则自动确认。配置模型后，相关原帖、发布时间和最多 8 条 Tibo 引用/回复祖先会发送到所选模型接口；回复辅助关闭时不发送附近回复。不会发送 X 登录 Cookie。模型服务可能产生费用，HTTP 地址没有传输加密。

## 模型判断

监测设置可为新帖选择 LLM 或 JEV。选择只影响随后发现的新帖，已有帖子的判断渠道及结果不因切换而重跑。只有帖子自身包含 reset 词形才进入所选模型队列；普通帖子保留原文但不调用模型。LLM 支持 Chat Completions、Responses 和 Anthropic Messages；配置单独保存在 `userData/tibo-radar-model.json`，API Key 使用 Electron safeStorage 加密，不返回给界面。

JEV 使用 Vercel AI Gateway 的 `typesafe-ai/jev`，固定请求 `https://ai-gateway.vercel.sh/v1/evaluate`，密钥单独加密保存在 `userData/tibo-radar-jev.json`。它是与 LLM 二选一的独立判断渠道，不读取或覆盖另一渠道的结果。每轮最多处理 4 条 reset 帖，失败退避。第一轮判断普通重置、Banked 和时间线索；仅普通预告再用第二轮从 `00:00` 到 `24:00` 及“未知”中选时，`24:00` 是次日零点。主帖明确时刻优先；开启回复辅助后，可用关联帖的时间，冲突候选不生成 ETA；仅日期时另标既有 01:00 预测。日期、时区和来源由本地代码独立解析并校验，完成通知必须有主帖明确措辞。相同原文重抓复用已有结果。


- 只筛选帖子自身的 reset 词形，新帖优先，每轮最多分析 4 条。旧帖逐轮补齐。
- Chat Completions / Responses 请求 JSON object 模式；Anthropic 按提示输出 JSON。全部结果经 JSON.parse 和字段校验，不接受 Markdown 代码块或损坏 JSON。
- 提取 kind、banked、forecastType、evidence、timeEvidence、time、confidence。证据必须是原帖原文；低置信度降为提及。置信度是模型自报值，不是准确率保证。
- 时间由程序计算，明确区分原文明示时区与假定太平洋时区。Banked 不生成普通重置 ETA。没有完成通知，不会因到时或模型失败而确认重置。
- 分类缓存绑定原文、上下文、模型地址/格式/名称和提示版本。未判断或失败时保留帖子，不回退到正则自动确认；失败至少等待 5 分钟再重试。
- 仅有明确日期或星期而没有时刻时，按既有用户规则预测当地 01:00；“midnight / end of day”等非数字措辞沿用该规则。界面标“预测”，同时写“未通报时间”，不把它当作原帖承诺。明确 00:00、12am、24:00 等数字时刻或相对间隔不改写。默认 America/Los_Angeles，自动使用冬夏令时（规则预测夏季对应北京时间 16:00，冬季 17:00）；日期按原帖发布时间解析。仅“soon”等连日期也不明确的措辞继续待定。Banked 不生成普通重置 ETA。
- 预告为黄色“等待重置”；到预计时间仍无完成通知时为橙色“暂未确认”，观察两小时后继续监测，不自动确认。时间字段不合法时保留已校验的预告并标注时间未明确。单条模型输出校验失败不阻塞后续帖子；网络或鉴权错误才停止该批次。
- 提示版本更新时，旧缓存先用原有 JSON 本地重校验，避免历史帖子全部重新调用模型。显式单帖重分析可通过 `scripts/reanalyze-tibo-post.cjs --id=<帖子ID>` 运行，结果独立暂存，重启后台时导入，不覆盖运行中的整份缓存。
- 界面分别显示抓取异常和模型分析异常，模型时间不明确不再被误报为抓取失败。
- 配对只采用引用/回复关系，未找到关系的完成帖单独展示，不凭模型猜测配对。
- 关闭 Monitor 后不会继续轮询。更改后台代码后需要重启应用。
